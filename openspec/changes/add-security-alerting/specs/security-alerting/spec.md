## ADDED Requirements

### Requirement: 想定外のSSHログイン成功を通知する
システムは、n8n VMの`sshd`へのSSHログインが成功し、それが「許可したユーザーかつIAPの送信元」のいずれにも当たらない場合に、通知しなければならない(SHALL)。

#### Scenario: 許可していないログインは通知される
- **WHEN** 許可していないユーザー、または`35.235.240.0/20`以外の送信元のログインが成功する
- **THEN** 通知が送られる

#### Scenario: CIのデプロイは通知されない
- **WHEN** CIのユーザーがIAP経由でログインする
- **THEN** 通知は送られない

### Requirement: 想定外の主体のシークレット読み取りを通知する
システムは、許可リストにない主体がシークレットのバージョンを読み取った場合に、通知しなければならない(SHALL)。

#### Scenario: 許可していない主体の読み取り
- **WHEN** 許可リストにない主体が`AccessSecretVersion`を実行する
- **THEN** 通知が送られる

### Requirement: ファイアウォールとIAMの変更を通知する
システムは、ファイアウォールルールの作成・変更・削除と、IAMポリシーの設定を、実行した主体にかかわらず通知しなければならない(SHALL)。

#### Scenario: ルールが変更される
- **WHEN** ファイアウォールルールが変更される
- **THEN** 通知が送られる

### Requirement: n8nのログイン失敗の連続を通知する
システムは、n8nの`POST /rest/login`の401が、定めた時間内に閾値以上になった場合に通知しなければならない(SHALL)。

#### Scenario: パスワードの総当たり
- **WHEN** 10分間に5回以上のログイン失敗が起きる
- **THEN** 通知が送られる

### Requirement: 通知はメールで受け取り、量を抑える
システムは、通知をメールの通知チャンネルへ送らなければならない(SHALL)。同じポリシーの通知は、設定した間隔より頻繁に送ってはならない(SHALL NOT)。

#### Scenario: 連続する事象
- **WHEN** 同じ条件に一致する事象が短時間に続く
- **THEN** 通知は設定した間隔ごとにしか送られない

### Requirement: 通知先と許可リストを公開しない
システムは、通知先のメールアドレスと運用者を特定する値を、リポジトリにもCIのログにも平文で出してはならない(SHALL NOT)。

#### Scenario: planの出力
- **WHEN** CIが`terraform plan`を実行する
- **THEN** 該当する値はsensitiveとして伏せられる
